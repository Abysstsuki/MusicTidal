# 歌曲批量加入常规待播

点歌搜索、个人／搜索歌单详情和房间歌单详情可点击“批量选择”，勾选歌曲后加入常规待播。翻页保留已选歌曲，当页全选仅选择当前页；每批最多 100 首。更换搜索词、平台或歌单、返回目录和关闭弹窗会清空选择。

点歌面板的批量操作位于搜索栏上方，可先开启批量模式再搜索。修改搜索词时清空已选，但保留批量模式；关闭面板或点击“退出选择”恢复单曲操作。批量模式下点击歌曲行可切换选择，选中行高亮，原有单首入队按钮仍独立工作。

入队按页码和页内顺序排列，每批内部按平台＋歌曲 ID 去重；允许再次加入正在播放或已在队列中的歌曲。批量入队保持当前播放模式，当前歌曲继续播放。歌单模式下，批量歌曲等房主切换常规模式后播放。

部分成功时只清除已成功入队的选择，失败项显示原因并可单独重试。房主未有效绑定的平台不能新选歌曲；已选歌曲在授权变化后保留，仍可取消，恢复授权后可重试。网络中断导致请求结果不明确时，应先查看常规待播再决定是否再次提交。

## 接口

`POST /api/rooms/:roomId/queue/add-batch`，需登录且为房间成员。

```json
{ "songs": [{ "provider": "netease", "id": 123 }, { "provider": "qqmusic", "id": 123 }] }
```

请求包含 1～100 个合法标识。非法请求整体返回 400，不入队。合法请求返回：

```text
{ success: true, added: QueueSong[], failed: [{ provider, id, code, message }], duplicateCount: number }
```

歌曲详情、媒体标识及付费标签由服务器使用房主凭据重新读取。每个平台独立处理错误；请求完成后重新检查成员资格和授权版本，再按原请求顺序一次性追加成功歌曲。所有成功项的来源为 manual，WebSocket 协议和单曲接口不变。

## 部署

无数据库迁移。先同步后端代码，在服务器的 backend 目录执行：

```text
docker compose --env-file .env.docker up -d --build backend
docker compose --env-file .env.docker ps
```

后端正常后发布 Cloudflare 前端。后端重启会结束内存中的房间，数据库中的用户与音乐账号绑定保留。
