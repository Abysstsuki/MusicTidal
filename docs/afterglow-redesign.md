# MusicTidal · Afterglow 重构

采用第 3 个视觉方向的布局：三行同步歌词、底部悬浮播放控制，点歌、待播和聊天使用按需打开的浮层。按后续需求，舞台背景改为当前歌曲的专辑封面，随切歌更新。延续多人一起听歌的应用流程。

## 使用

在 `frontend` 执行 `npm run dev`，打开 `http://localhost:3000/` 浏览房间大厅，登录并加入房间后进入听歌页面。视觉预览与模拟歌曲、歌词、队列等功能已移除，没有预览 URL 入口。

沿用既有 `NEXT_PUBLIC_BACKEND_URL`、`NEXT_PUBLIC_WS_URL` 和后端房间 API；搜索、队列、账号和歌词使用真实服务。静态导出沿用现有配置，生产构建读取生产环境配置。

## 状态与播放

- `MusicContext` 管理唯一的 WebSocket 连接、重连、登录用户、在线用户、聊天、队列和播放快照。关闭浮层不会丢失实时更新。
- WebSocket 更新优先于较早发出的 REST 响应，防止旧响应覆盖新歌曲或队列。
- 浏览器暂停只暂停自己的音频。恢复播放会对齐服务器的当前时间；浏览器拒绝自动播放时显示加入播放的提示。
- 下一首由服务器为所有人切换。浏览器的 `ended` 事件不再请求跳歌。
- 服务端按毫秒歌曲时长计时，保存并取消旧定时器。加载锁避免并发点歌启动多首，版本号避免跳歌后较早的音频 URL 覆盖新歌曲。不可播放的歌曲会跳过。
- 队列、聊天、在线用户仍保存在进程内存，服务端重启会清空；本次没有引入房间或数据库持久化。

## 视觉与交互

背景读取 `currentSong.prcUrl`，铺满视口并保留深色遮罩以保障歌词和导航可读；加载完成后淡入。切换封面地址时重置图片状态，避免上一首歌曲或加载失败状态残留。没有歌曲、没有封面或加载失败时显示纯深色舞台，播放器与列表使用专辑图标兜底。旧的 ImageGen 天体图已不再用于界面。歌词和全部控件均由 React 渲染。歌词专用 Noto Sans SC 可变字体由 `next/font` 托管，主行使用 600 字重，相邻行与译文使用 400，支持中英文统一排版；界面英文仍使用 Inter，图标使用现有 MUI 图标库。

1100px 以下的紧凑窗口和手机默认收起浮层，保持封面、歌词与播放控制可见。短横屏使用紧凑布局。点歌打开后聚焦输入框，Escape 关闭面板并返回触发按钮；登录与在线列表使用原生 dialog 提供键盘焦点约束。

## 验证

已执行前端生产构建、前后端 TypeScript 检查、修改文件的 ESLint 检查和 `git diff --check`。构建仅剩原有未使用组件 `MusicItem.tsx` 的图片优化警告。

在 `backend` 执行 `node --test tests/songQueueService.test.cjs`，5 项测试覆盖毫秒时长、自动结束、取消旧定时器、并发点歌、过期 URL 和不可播放歌曲。测试隔离网易云、WebSocket 和数据库依赖。

浏览器已检查桌面、手机竖屏与横屏；预览模式的搜索、加入待播、置顶、移除、聊天、在线列表、播放暂停、静音及歌词切换均已操作。真实模式检查了空闲状态与登录/注册表单的展示和必填验证。真实网易云音频、数据库登录、多浏览器同步仍需在后端服务可用后联调。
